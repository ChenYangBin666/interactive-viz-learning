XGBoost / 模块 06

工程优化

XGBoost 之所以在实践中如此高效，不仅因为其算法设计，更因为一系列精心的工程优化。 本模块将深入探讨列块压缩存储、近似分位数算法、稀疏感知、缓存友好设计以及并行与分布式计算策略。

1

列块压缩存储 (Column Block / CSC)

XGBoost 在训练前将每个特征独立排序，并以 列块 (Column Block) 的形式存储。 每个块保存排序后的特征值及其对应的行索引。

预排序只需执行 一次。之后每轮 boosting 扫描候选分裂点时， 只需线性遍历已排序的列，时间复杂度为 $O(n)$，无需重新排序。

右侧演示：原始数据表被拆分为独立排序的列块。点击按钮观察分裂扫描过程。

2

近似算法与分位数

当数据量巨大时，枚举所有可能的分裂点代价过高。XGBoost 使用 加权分位数草图 (Weighted Quantile Sketch) 来选取候选分裂点。

关键思想：以二阶导数 $h_i$ (Hessian) 作为权重。Hessian 越大的区域， 模型越"不确定"，需要更精细的候选点。

形式化：找到候选集 $\{s_1, s_2, \ldots, s_l\}$ 使得 $|r_k(s_j) - r_k(s_{j+1})| < \epsilon$，其中 $r_k(z) = \frac{\sum_{i: x_{ik} < z} h_i}{\sum_i h_i}$ 是加权秩函数。

稀疏感知 (Sparsity-Aware)

真实数据中常有缺失值或大量零值。XGBoost 的策略：在每个分裂节点， 自动学习缺失值的默认方向。

具体做法：分别尝试将所有缺失值样本分到左子节点和右子节点， 选择增益更高的方向作为默认方向。

这意味着 XGBoost 不需要对缺失值做额外的填充预处理， 而是在训练过程中自然地处理缺失值。

缓存友好设计

在精确贪心算法中，梯度统计量 $(g_i, h_i)$ 按特征排序后的顺序被访问。 但排序后的行索引是非连续的，导致频繁 缓存未命中 (Cache Miss)。

XGBoost 的解决方案：分配一个内部缓冲区，按排序后的索引 预取 (Prefetch) 梯度统计量，使后续访问变为顺序访问。

对于近似算法，选择合适的块大小 (block size) 同样关键—— 块太小则并行度不够，块太大则缓存溢出。经验最佳值: $2^{16}$ 行。

并行与分布式

XGBoost 的并行不是树级别的并行，而是 特征级别的并行： 不同 CPU 核心同时扫描不同特征的候选分裂点，最后合并选出最优分裂。

在分布式场景中，数据按行分布到不同机器。每台机器构建本地直方图， 然后全局归约 (AllReduce) 合并统计量。

特征并行 + 列块存储使得 XGBoost 能够高效利用多核 CPU。 分布式 AllReduce 架构则支持 TB 级别数据训练。
