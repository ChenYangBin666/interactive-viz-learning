多级Cache (Multi-Level Cache)

探索L1/L2/L3多级缓存的设计权衡、缺失率分析、包含策略与性能计算

🏗

1. 为什么需要多级Cache

单级缓存面临一个根本性的矛盾：容量和速度不可兼得。小容量Cache访问快但命中率低，大容量Cache命中率高但访问慢。多级Cache架构通过分层设计解决了这个两难困境：

  • L1 Cache — 最小、最快，紧贴CPU核心，容量32-64KB，延迟~1ns
  • L2 Cache — 中等容量和速度，256KB-1MB，延迟~3-10ns
  • L3 Cache — 最大、多核共享，4-64MB，延迟~10-30ns
  • 主存 — 容量最大但最慢，延迟~50-100ns

关键洞察：多级Cache利用局部性原理，让大部分访问在最快的L1层完成，只有少量缺失才需要访问更慢的层级，从而在整体上接近"大容量+低延迟"的理想效果。

2. L1/L2/L3 设计权衡

每级Cache的设计目标不同，导致在容量、关联度、延迟等参数上的选择截然不同：

  • L1：优化速度 — 容量小、低关联度(或直接映射)、分离的指令/数据Cache(Split I/D)
  • L2：优化缺失率 — 容量更大、更高关联度、统一Cache(Unified)
  • L3：多核共享 — 容量最大、最高关联度、用于减少访存

3. 本地缺失率 vs 全局缺失率

理解多级Cache性能的关键在于区分两种缺失率：

  • 本地缺失率 (Local Miss Rate)：该级缺失次数 / 该级访问次数
  • 全局缺失率 (Global Miss Rate)：该级缺失次数 / CPU总访问次数

全局缺失率才是衡量性能的关键指标。公式如下：

$$\text{Global Miss Rate}_{L2} = \text{Local Miss Rate}_{L1} \times \text{Local Miss Rate}_{L2}$$ $$\text{Global Miss Rate}_{L3} = \text{Local Miss Rate}_{L1} \times \text{Local Miss Rate}_{L2} \times \text{Local Miss Rate}_{L3}$$

为什么全局缺失率更重要？ 因为每一级Cache都在"过滤"访问请求。L2只看到L1缺失的请求，L3只看到L2缺失的请求。即使L2的本地缺失率很高，真正穿透到主存的全局缺失率可能很低。

4. 包含与排他策略 (Inclusive vs Exclusive)

多级Cache之间的数据存放关系有三种主要策略：

  • 包含(Inclusive)：L2包含L1中所有数据的副本。优点：一致性简单；缺点：有效容量减少。
  • 排他(Exclusive)：L1和L2没有重叠，数据只在一个层级。优点：有效容量最大；缺点：驱逐操作复杂。
  • NINE (非包含非排他)：灵活策略，不强制包含或排除关系。实现简单但一致性处理复杂。

5. 多级AMAT计算

多级Cache的平均访存时间 (AMAT) 扩展公式：

$$\text{AMAT} = T_{L1} + MR_{L1} \times \left( T_{L2} + MR_{L2} \times \left( T_{L3} + MR_{L3} \times T_{mem} \right) \right)$$

其中 \(T\) 为命中时间，\(MR\) 为本地缺失率。每一层的缺失代价就是访问下一层的时间。
