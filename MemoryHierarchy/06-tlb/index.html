TLB — 快表

Translation Lookaside Buffer: 虚拟地址到物理地址的硬件加速器。 每次内存访问都依赖它 —— 理解 TLB 就理解了现代处理器性能的关键。

地址翻译加速 内容寻址存储器 ASID 标签 VIPT / PIPT
1

为什么需要 TLB

页表存放在主存中。没有 TLB 时，每次数据访问都需要先访问页表（一次额外的内存访问），有效访问时间翻倍。

TLB 是 CPU 内部的高速缓存，专门缓存最近使用的页表项，让绝大部分地址翻译在 1 个时钟周期内完成。

TLB 结构

TLB 本质上是一个内容寻址存储器 (CAM)：输入 VPN，所有表项同时比较，命中时直接输出对应的 PPN。

每个 TLB 表项包含：Valid · VPN Tag · PPN · Dirty · ASID

3

TLB 查找流程

完整的地址翻译流程：VA → TLB 查找 → 命中则直接获得 PA；未命中则查询页表 → 更新 TLB → 获得 PA。

TLB Miss 处理

TLB 未命中后，需要遍历页表 (Page Table Walk) 来找到正确的物理帧号。

x86 (硬件管理)：MMU 硬件自动遍历页表，透明地填充 TLB。
MIPS / RISC-V (软件管理)：TLB 未命中触发异常，由 OS 处理。

页表查找代价:200 ns
额外内存访问:2 次

上下文切换与 ASID

进程切换时，TLB 中的映射属于旧进程，新进程不能使用。

方案 A：切换时刷新整个 TLB —— 简单但代价高昂（冷启动）。
方案 B：为每条 TLB 表项添加 ASID（Address Space Identifier），不同进程共存于 TLB。

TLB 与 Cache 联动

完整内存访问路径：VA → TLB → PA → Cache → 数据。TLB 和 Cache 的配合方式决定了总延迟。

PIPT — 物理索引物理标签

安全：Cache 使用物理地址，无别名问题。
串行：必须先完成 TLB 翻译，再查 Cache。

VIPT — 虚拟索引物理标签

快速：Cache 索引用虚拟地址（与 TLB 并行），标签比较用物理地址。
约束：Cache 大小 / 相联度 ≤ 页大小时无别名。
