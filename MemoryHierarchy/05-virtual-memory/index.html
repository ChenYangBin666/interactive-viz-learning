虚拟内存

Virtual Memory -- 让每个进程拥有独立地址空间的核心抽象机制，实现内存隔离、地址空间扩展与按需加载

1

为什么需要虚拟内存

在没有虚拟内存的系统中，多个程序直接使用物理地址。如果进程 A 使用地址 0x1000，进程 B 也想用 0x1000，就会发生地址冲突。虚拟内存通过为每个进程提供独立的虚拟地址空间，完美解决了这个问题。

隔离保护

每个进程有独立的地址空间，无法访问其他进程的内存。操作系统通过页表的保护位实现安全隔离。

地址抽象

程序员无需关心物理内存布局。编译器始终假设从地址 0 开始，操作系统负责映射到真实物理地址。

超越物理限制

虚拟地址空间可以远大于物理内存。操作系统将暂不使用的页换出到磁盘，按需加载。

2

页表 (Page Table)

页表是虚拟内存系统的核心数据结构。它将虚拟页号 (VPN) 映射到物理帧号 (PPN/PFN)。每个页表项 (PTE) 包含若干控制位。

页表项字段：有效位 (Valid) 表示页是否在物理内存中；脏位 (Dirty) 表示页是否被修改过；保护位 (Prot) 控制读/写/执行权限；帧号 (Frame) 是物理帧地址。

4

页面错误 (Page Fault)

当访问的虚拟页不在物理内存中时（页表项 valid=0），CPU 触发页面错误异常。操作系统接管控制，从磁盘加载所需页面，更新页表后重新执行该指令。

页面错误处理流程

1
CPU 发出虚拟地址 -- 尝试访问一个虚拟页
2
查询页表 -- 发现 Valid=0，触发页面错误异常
3
OS 页面错误处理程序 -- 确定页面在磁盘上的位置
4
磁盘 I/O -- 读取页面到空闲物理帧 (~10ms)
5
更新页表 -- 设置 Valid=1，填入物理帧号
6
重新执行指令 -- 这次页表命中，正常翻译

6

多级页表 (Multi-Level Page Tables)

单级页表的问题：假设 32 位虚拟地址、4KB 页面，则需要 2^20 = 1,048,576 个页表项。若每项 4B，单个页表就要 4MB -- 每个进程都需要一个！

解决方案：多级页表。将一级页表拆成页目录 + 二级页表，只为实际使用的地址区域分配二级页表。对于稀疏地址空间，可节省大量内存。

反向页表 (Inverted Page Table): 另一种方案是按物理帧建立索引，每个帧一个表项记录哪个进程的哪个虚拟页在此帧。优点是页表大小与物理内存成正比（而非虚拟地址空间），缺点是查找需要哈希搜索。PowerPC 和 IA-64 曾使用此方案。
