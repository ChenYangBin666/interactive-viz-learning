Parallel Training — 特征并行 / 数据并行 / 投票并行

1

特征并行 (Feature Parallelism)

每个 Worker 持有全部数据行，但只负责一部分特征列。各 Worker 在自己的特征子集上寻找最佳分裂点，然后通过通信选出全局最优分裂。

瓶颈：每个 Worker 仍需存储完整数据集，通信开销为 \(O(W)\) 次分裂结果广播，其中 \(W\) 为 Worker 数量。

点击"播放动画"开始
特征并行将数据矩阵按列（特征维度）切分到不同 Worker 上。
2

数据并行 (Data Parallelism)

每个 Worker 持有一部分数据行，各自构建本地直方图，然后通过 All-Reduce 合并为全局直方图，再在全局直方图上找最优分裂点。

优势：通信量为直方图大小 \(O(\text{features} \times \text{bins})\)，远小于数据本身的大小。

点击"播放动画"开始
数据并行将数据矩阵按行（样本维度）切分到不同 Worker 上。
3

投票并行 (Voting Parallelism)

LightGBM 的创新方案。每个 Worker 先在本地找出 top-k 候选分裂点，然后进行投票。只有票数最高的候选才在全局直方图上精确评估，大幅减少通信量。

关键思路：大多数 Worker 会在相似的特征上发现好的分裂点，因此投票能有效筛选出全局最优候选。

点击"播放动画"开始
投票并行通过本地 top-k 选举和全局投票来减少不必要的通信。

加速比可视化 (Speedup)

根据 Amdahl 定律，加速比受串行部分比例限制：$$S(p) = \frac{1}{(1-f) + \frac{f}{p}}$$ 其中 \(f\) 为可并行化的比例，\(p\) 为 Worker 数量。通信开销进一步降低实际加速比。
