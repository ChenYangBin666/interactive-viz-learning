AMAT 模型

Average Memory Access Time

平均存储访问时间 (AMAT) 是衡量缓存性能的核心指标，综合考虑了命中时间、缺失率和缺失惩罚三个因素。

含义：AMAT 越小，缓存系统性能越好。它由三个参数共同决定 —— 命中时间（访问缓存的固有延迟）、缺失率（访问未命中的比例）和缺失惩罚（未命中时需额外付出的代价）。

3C 模型

Compulsory · Capacity · Conflict

所有缓存缺失可分为三类（3C 模型），理解它们有助于针对性优化。

强制缺失 (Compulsory)

首次访问某块数据时必然发生的缺失，也叫冷启动缺失。无论缓存多大都无法避免。

容量缺失 (Capacity)

工作集超出缓存容量时，即使是全相联缓存也会发生的缺失。

冲突缺失 (Conflict)

多个块映射到同一组，即使缓存整体未满也发生淘汰。仅在非全相联缓存中出现。

缺失率优化

减少 3C 缺失

针对三种缺失类型，有不同的优化策略。调节下方参数，观察各类缺失的变化。

优化方向：强制缺失 → 预取 (Prefetching)；容量缺失 → 增大缓存；冲突缺失 → 提高相联度。

权衡：增大缓存和提高相联度能有效降低缺失率，但存在硬件成本增加和访问延迟上升等代价。注意观察图中的收益递减现象。

缓存友好编程

Cache-Friendly Programming

程序的内存访问模式直接影响缓存命中率。空间局部性好的代码能充分利用缓存行。

示例 1：行优先 vs 列优先遍历

行优先遍历缓存友好
// 按行遍历：步长 = 1
for (i = 0; i < N; i++)
  for (j = 0; j < N; j++)
    sum += a[i][j];
// 连续访问相邻内存
列优先遍历缓存不友好
// 按列遍历：步长 = N
for (j = 0; j < N; j++)
  for (i = 0; i < N; i++)
    sum += a[i][j];
// 每次跳跃 N 个元素

示例 2：AoS vs SoA

Array of StructuresAoS - 分散
struct Particle {
  float x, y, z, vx, vy, vz;
};
Particle p[N];
// 只需 x 却加载全部字段
for (i = 0; i < N; i++)
  process(p[i].x);
Structure of ArraysSoA - 紧凑
struct Particles {
  float x[N], y[N], z[N];
  float vx[N], vy[N], vz[N];
};
Particles p;
// x 数组连续，充分利用缓存行
for (i = 0; i < N; i++)
  process(p.x[i]);
